# Blog engine audit and rollout · November 19, 2026

The review traced the portable engine, provider adapters, content and asset generation, public
outputs, publication workflows, indexing, and measurement. It also checked public feed, robots,
article, and sitemap responses for two legacy adopter sites. Publication, release permissions,
schedules, and route rendering are owned by the website or control plane that installs this package.

## Findings and changes

| Area | Finding | Change in this PR |
|---|---|---|
| Daily delivery | Retries requested a new post each time. A refresh could satisfy the cadence report. | Website-selected daily targets use the UTC publication date and the persisted corpus. A retry fills only the remaining target. Per-site runs in one process serialize, and the GitHub template serializes publish jobs in the same repository. The daily scorecard reports exact missed dates over the last seven complete UTC days. |
| Editorial quality | The fallback could recycle an exhausted topic pool. Copy prompts encouraged artificial freshness and one prescribed quotation format as an AI tactic. | Optional fresh-topic enforcement fails before any model or image call when the pool is exhausted. Curated topics accept verified evidence. Prompts favor a useful example, decision criterion, or checklist, explicitly label hypothetical examples, and use as-of dates supported by evidence. Generation and refresh reject duplicate normalized titles and enforce the existing single-blockquote contract. |
| Refresh | A rewrite could bump dates without changing content. A recently edited first-ranked candidate could prevent the selection of the next eligible article. An unknown explicit slug could fall through to a different post. | Check cooldown before limiting candidates and skip unchanged refresh writes. Explicit slugs only refresh matching rows. |
| Publication and storage | AllWeb generation could obtain the revision of an existing slug and overwrite it. A future-dated row could be returned by the point reader. Malformed or repeated pages could be treated as a partial corpus. | Create requests omit an update revision. Refresh requires a verifiable published revision. Reader point and list paths enforce public status, date and tenant; malformed and repeated list pages surface errors. Supabase keeps unique inserts, scoped reads, and conditional published-row updates. No migration is needed. |
| Asset pipeline | A corrupt or missing watermark could allow an unwatermarked generated hero. | The AI hero falls back to the site's curated image when watermarking fails. Existing output sizes, responsive assets, and branded OG defaults still apply. |
| Public readiness | HTTP 200 alone could pass for a soft 404 or stale page; multiple entry points fetched the same article twice. | A single bounded verifier rejects redirects, explicit noindex and differing canonicals. Strict mode also requires a self-canonical HTML page and checks the rendered title and quick answer when the stored copy is supplied. |
| Submission and recovery | IndexNow errors skipped Google submission. Sitemap HTTP failures could look like success. Partial batches and interrupted runs could strand saved URLs. | Provider calls run independently and record actual responses. Ready pages in a partial batch can be submitted. Retry existing slugs or recover a bounded range of recent stored changes. The range recovery leaves syndication off to prevent repeat shares. |
| Discovery and markup | Future and draft content could reach generic output builders. An empty sitemap hub inherited today's date, and RSS could emit false enclosure sizes and order items incorrectly. | Discovery builders filter known non-public and future rows, use truthful dates or omit unknown ones, and generate canonical URLs. RSS sorts by publication date, uses known modification dates, and retains media markup when a byte length is unavailable. Article schema prefers the stored byline, supports organization authors, and lets templates omit FAQ markup. |
| Monitoring | Crawl checks used a generic blog prefix and could miss article-specific blocks. An index coverage label containing “indexed” could be misclassified, and citation reports conflated mentions with links. | The scorecard checks actual hub and article paths, newest raw HTML, and exact sitemap membership. URL Inspection supports OAuth and the existing site-scoped AllWeb gateway. Coverage tracks Google's selected canonical. Grounded citation probes count links to known blog articles separately from brand mentions. |
| Dependencies | The baseline npm audit flagged high-severity findings in sharp, undici, and zod. The package advertised Node 20.9 although its installed AI SDK requires Node 22. | Patched the resolved dependency versions and aligned the advertised runtime with the SDK and CI. Robots, HTML, sitemap, and API requests follow bounded verification paths. |

The filesystem store, Supabase adapter, and AllWeb adapter share the engine contract. Consider the
AllWeb control plane's existing revision-bound release receipt the durable retry record for sites
using brokered release. For a different backend, persist the changed slugs in its scheduler or job
record and resume discovery after delivery failures. Serialize jobs across processes at the scheduler
or database boundary. The daily target reads persisted posts and does not reserve a cross-process slot.

Source reachability checks cannot establish factual support. Use a small trusted-domain list and a
restricted egress policy or site-provided verification hook when the generation service can access
private networks. Route sensitive legal, financial, health, or safety topics through accountable
review and verify material claims against the source text. Supabase publication remains protected
by RLS on the public table and by a server-only write credential. AllWeb release still requires the
gateway's site and publish scopes.
[Supabase Data API security](https://supabase.com/docs/guides/api/securing-your-api),
[AllWeb blog automation](https://github.com/BizrnrAI/websites-control-plane/blob/main/docs/BLOG-AUTOMATION.md).

## November 2026 search and citation practices

1. Maintain a site-specific editorial queue with one distinct reader need per brief, primary evidence
   and original examples, and a subject-matter reviewer where accuracy matters. Use demand data as
   input. Keep commercial intent on its owner page and link supporting articles to it. Daily is an
   operational target. Google treats low-value scaled content created to manipulate rankings as spam.
   [People-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content),
   [Google spam policies](https://developers.google.com/search/docs/essentials/spam-policies).
2. Render the article body, practical answer, sources, byline, and dates in the initial HTML.
   Use descriptive titles, article links with ordinary hrefs, and a canonical URL shared by the hub,
   sitemap, structured data, and feed. Serve true 404/410 on missing or retired pages and a retryable
   503 during store outages. Expose meaningful image dimensions and a representative, crawlable hero.
   Monitor Core Web Vitals on mobile with real-user data where available.
   [Crawlable links](https://developers.google.com/search/docs/crawling-indexing/links-crawlable),
   [Canonical URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls),
   [Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article),
   [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals).
3. Use the verified Search Console property and keep its XML sitemap current. Submit canonical
   changed URLs to IndexNow for participating services. Keep meaningful page modification dates
   consistent with what readers can see. Google restricts the Indexing API to supported job postings
   and livestream pages. A successful sitemap submission or IndexNow response is a discovery signal.
   [Build and submit a sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap),
   [Google Indexing API scope](https://developers.google.com/search/apis/indexing-api/v3/using-api),
   [IndexNow protocol](https://www.indexnow.org/documentation).
4. For Google AI Overviews and AI Mode, focus on original helpful content that is indexed and
   eligible for snippets. Google Search ignores llms.txt and has no dedicated AI schema or required
   passage format. Keep FAQs when they help the reader and keep structured data aligned with visible
   content. For ChatGPT search, allow OAI-SearchBot and its published IP ranges at robots and CDN
   layers. GPTBot training preferences are independent. Check Bingbot, PerplexityBot, and
   Claude-SearchBot when those search surfaces are in scope.
   [Google generative AI guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide),
   [OpenAI crawler controls](https://developers.openai.com/api/docs/bots),
   [Perplexity bots](https://docs.perplexity.ai/docs/resources/perplexity-crawlers),
   [Anthropic crawler controls](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler).
5. Measure delivery against UTC publication dates. Track the time from publication to first indexed
   status, canonical coverage for a pinned group of URLs, and Search Console nonbrand impressions,
   clicks, and landing-page conversions. Compare like-for-like finalized windows. Measure grounded
   links with stable question sets and provider metadata, actual citations in Bing Webmaster Tools,
   and attributed referral traffic from ChatGPT. A citation probe is a sample of answers.
   [Google URL Inspection API](https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect),
   [Bing AI Performance](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/),
   [ChatGPT Search](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt).

## Rollout acceptance for each website

1. Pin the reviewed engine revision and adopt the direct publishing or authorized brokered path.
   Use Node 22 or newer. Confirm the public routes read the same published rows as the writer.
2. Assign one scheduling owner. For autonomous projects, use a daily trigger and a target of one
   new post per UTC day. Maintain a replenished editorial queue and enable
   `content.requireFreshTopic`. Review-required sites need a daily review and release path with
   an authorized reviewer. [Workflow and recovery setup](WORKFLOWS.md).
3. Configure the canonical host, sitemap, site-specific credentials and cache invalidation.
   Enable `indexing.requireCanonicalHtml` after validating the article heading and answer. Use the
   site's real access policy for search and retrieval crawlers.
4. Verify delivery using a real approved article. Check its saved slug, raw HTML, hub link, feed
   and sitemap membership, provider receipts, and the strict daily scorecard. Reconcile pending
   submissions independently of generation. Compare coverage and citation measurements on the
   same selected URLs as the rollout matures.
