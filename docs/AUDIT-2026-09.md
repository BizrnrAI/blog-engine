# Repository review, 2026-09-03

Scope: all source modules, public adapter surfaces, storage schema, workflow generators and
reusable workflows, examples, package/build contract, documentation, and regression tests.
Baseline: v1.3.2, 150 passing tests, no installed dependency advisories. This change prepares v2.

## Verification

- The complete TypeScript/test/build/docs gate is required before release.
- Added behavioral tests for punctuation, direct writes, refresh sources, full-corpus reads,
  tenant/status failures, concurrent contexts, dry-run behavior, live checks, workflow output,
  crawler rules, and safe schema serialization.
- SQL is exercised in a local PostgreSQL-compatible PGlite instance with a minimal Supabase
  storage fixture, including existing-row repair, future writes, idempotent reapplication,
  preservation of dates/slug/status, and row-level public-read policy. This is not a production
  migration or proof of compatibility with a custom adopter schema.
- Dependency audit reported zero vulnerabilities. Dependencies were not changed speculatively.

## Deployment evidence and remaining scope

The engine repository had no production site registry or Actions secrets. No production Supabase
migration or post publication was attempted from this checkout. Package/build verification does
not prove that a live website adopted the new version.

Seven open content PRs were confirmed in `Iowa-Contractors/contract-iowa` (#164, #176, #186, #192,
#198, #204, #218). Its generator is a native fork and the website is a static export of committed
Markdown. The legacy generation workflow was disabled to stop further PR creation; pending PRs
and existing content were preserved. Backfill plus website rendering/deployment changes are still
needed before that publisher can be re-enabled. The template repository also has old stamped
workflows; the central engine cannot rewrite those by releasing a package.

AllWeb gateways can enforce their own publication scopes and review requirements. This release
keeps those authorization boundaries intact. An authorized operator must change site policy
where autonomous publication is currently forbidden.

## Practical limitations

A reachable citation URL does not establish claim-level support. Site-specific evidence and
claims validators remain necessary. Search submissions, question headings, passage lengths, and
schema do not guarantee rankings or AI citations. Source URLs are protocol/host checked; a host
allowlist is recommended for authoritative research, and network-level egress policy remains the
runtime's responsibility.

The service has per-run isolation, not distributed editorial reservations. Website schedulers
must serialize publishing and enforce their own volume policy. Unique new-post inserts prevent
silent overwrites, but a failed run can leave uploaded assets without a post; automatic orphan
asset deletion is not part of this release.

The legacy low-level file API and reviewed-release adapter remain available for compatibility.
Direct-service/workflow adoption is required to eliminate content PRs. Curated fallback images
remain website-owned assets; sites must supply a valid fallback and watermark asset in their
runtime root. Source quality and the public rendering integration must be verified per website.
