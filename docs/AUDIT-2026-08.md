## 2. Incident: SDBG autoblog silent outage

- **Symptom:** every `autoblog.yml` run since 2026-07-03 ended `failure`
  (last success 2026-07-01). Generation, gates, and branch push all succeeded;
  the run died at `peter-evans/create-pull-request` with
  *"GitHub Actions is not permitted to create or approve pull requests."*
- **Root cause:** repository setting `actions/permissions/workflow` was
  `default_workflow_permissions=read`, `can_approve_pull_request_reviews=false`
  (KP, the healthy sibling, is `write`/`true`). This is gotcha #1 in
  [WORKFLOWS.md](WORKFLOWS.md); the setting had evidently reverted or was never
  applied to this repo.
- **Fix applied:** `gh api -X PUT repos/bizrnr/SDBG/actions/permissions/workflow
  -f default_workflow_permissions=write -F can_approve_pull_request_reviews=true`
  — verified readback.
- **Residue:** 19 unmerged `autoblog/sdbg-<run-id>` branches, each holding one
  generated post + images that were never reviewed. Recommended: delete them
  (`gh api repos/bizrnr/SDBG/branches?per_page=100 --jq '.[].name' | grep ^autoblog/ |
  xargs -I{} gh api -X DELETE repos/bizrnr/SDBG/git/refs/heads/{}`) rather than
  mass-publishing seven weeks of backlog, which would violate the cadence rule.
- **Lesson → engine:** a red cron must page someone. Added to WORKFLOWS.md; the
  roadmap adds a scorecard/alert surface so this class of failure is caught in
  a day.
